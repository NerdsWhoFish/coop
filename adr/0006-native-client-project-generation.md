# Generate the Xcode project and Swift API client from text sources

Status: accepted
Date: 2026-08-16

## Context and Problem Statement

Coop has two native applications that share one HTTP contract and must remain reviewable without treating Xcode's generated project structure as hand-authored source.
The backend contract already lives in `api/openapi.yaml`, and duplicating request and response models in Swift would turn every backend change into a manual synchronization task.
The Xcode project presents the same problem at a smaller scale: manually editing the project file produces opaque diffs and makes target settings difficult to review.

## Considered Options

* Commit a hand-maintained Xcode project and write the networking layer by hand.
* Commit a hand-maintained Xcode project while generating only the Swift API client.
* Generate both the Xcode project and the Swift API client from text sources.

## Decision Outcome

Chosen option: generate both artifacts from text sources.

`CoopKit` uses Apple's Swift OpenAPI Generator build plugin with the repository's OpenAPI document symlinked into the package target.
Generated Swift is build output and is not committed.
The application project is generated by XcodeGen from `ios/CooperTheCop/project.yml`, while application source, tests, entitlements, and resources remain ordinary committed files.

### Consequences

Good:

* A contract change regenerates the native types and operations during the build, so incompatible client code fails to compile.
* Project settings have compact, readable diffs.
* `CoopKit` can be built and tested independently of either application.
* The child application can reuse the same generated operations without copying authentication or transport code.

Bad:

* Contributors must install XcodeGen before regenerating the application project.
* Xcode build-plugin behavior is another dependency in the build chain and must be exercised in CI.
* XcodeGen upgrades can rewrite large portions of the generated project, so its version must be changed deliberately and the resulting project diff reviewed.
